# Frontend verification

Run `npm run build`, `npm test`, and `npm run test:ui` from the repository root. Browser tests use an isolated Tauri IPC fixture and generated test-pattern media served with byte-range support. No fixture data is included in the application build. The pinned FFmpeg runtime generates test fixtures and supplies the limiter PCM reference.

The optional actual-media check runs with `SCREENRECORD_MEDIA_TEST_DIR` pointing to a captured project containing `screen.mp4` and `system.wav`. It serves only those two files on a temporary loopback HTTP server with byte-range support, then checks decoding, advancing playback clocks, and the AudioWorklet path for captured float WAV. The test routes its audio to a zero-gain output. This check validates Chromium decoding and CORS over HTTP, not Tauri asset-protocol behavior.

## Design decisions

Preview occupies the main area because the editor's primary task is judging the result. A single project toolbar and collapsible library preserve working space. Inspector tools use readable vertical navigation; the timeline has sticky track headers, populated tracks, and a 260px scrollable viewport that reduces to 200px on shorter windows. At 1920x1080 the tested preview area is 656px high; at 900x640 it remains 280px high. Segoe UI follows Windows typography and avoids a downloaded font dependency. Neutral surfaces distinguish tools from footage; amber identifies actions and selected zooms. Dark and light themes share semantic tokens. Motion is limited to video playback and control feedback. There are no decorative brand dots, left-edge card accents, promotional text, or fake library entries.

Preview Fit/100%/200% changes only viewing magnification, never export geometry. The recorded-source status distinguishes a hidden webcam overlay from a recording without a camera track. Recording setup offers an explicit Enable preview action; selecting a device alone does not open it. Start, Cancel, Escape, and application close await preview cleanup. User-chosen camera, microphone, system-audio, and frame-rate preferences are remembered and checked against refreshed devices, without automatically enabling a live preview.

Recording setup offers a remembered 0/3/5-second countdown, defaulting to 3 seconds. Existing edits save and preflight devices stop before the timer. Cancel receives focus; its button and Escape prevent the start command. No new capture is requested before the monotonic deadline. The floating `?overlay=recording` entry does not mount the editor or enumerate/open devices. It reads recording state and JPEG snapshots from the existing capture process, shows authoritative elapsed time, and sends the displayed project UUID with Pause/Resume/Stop. Polling is serial at 250ms; operation epochs, project IDs, generation, and sequence checks discard late frames. Paused camera output is hidden and labeled. Main-window controls use the same commands and ignore polls started before a state-changing action. Native positioning uses dragging or focused arrow-key steps; Show app calls the backend restore command. These IPC tests do not verify native always-on-top behavior, monitor clamping, window exclusion from capture, or physical pause/resume synchronization.

Clicking a visible camera or mask selects its properties. Dragging moves it; corner handles resize it. Keyboard nudges and numeric properties remain available. A gesture is one undo step; Escape, pointer cancellation, or becoming busy restores the original geometry without adding an undo step. Preview controls stay outside the exported video.

Camera layouts are Bubble over screen, Camera only, and Split screen and camera. Bubble retains position, size, and shape manipulation. Split places screen left and camera right in landscape, or screen above camera in portrait; camera share is adjustable. Fixed panes use the same integer geometry and centered cover crop as the renderer. Camera gaps and EOF retain the reserved background. Camera only never reveals screen, including when the camera is disabled or its media is absent. Source-mask drawing and manipulation are disabled there, with an explicit switch back to Bubble. Fullscreen camera, mask, crop, and subtitle privacy edits synchronously clear stale pixels before waiting for decoded seeks, without cancelling an active mask gesture.

Appearance presets contain only aspect ratio, background, padding, corner radius, cursor styling, camera styling/layout, and subtitle styling. Applying a preset is one undoable edit and preserves cuts, trim, crop, zooms, music, audio levels, subtitle text, redactions, and media metadata. Missing camera media prevents Camera only preset application; other presets disable its camera. Built-ins remain available if custom settings cannot load. Custom save/delete uses native settings storage, exposes retryable errors and named deletion confirmation, and discards replies after the panel unmounts. Headless tests mock this storage API; native file validation and atomic persistence are covered by the core/backend tests.

## Integration boundaries

The backend owns recording and export state, input/path validation, and safe shutdown. Frontend closing always prevents Tauri's default destructive close handler, saves pending changes, then calls `close_app`, whose backend must refuse while a job is active. The close listener registers before initialization. Duplicate requests are ignored while closing; a 10-second save deadline reports a visible error and preserves edits. A save that completes after the deadline does not trigger a delayed close without a new request. Editing is locked during recording and project-replacing operations. Autosave sends only `{id,name,edits}` and retains immutable cursor data outside Vue's deep proxy tracking.

The project menu supports right-click, Shift+F10, ContextMenu, and a visible actions button. Deletion requires a named confirmation with Cancel initially focused. Pending edits save first; the current preview releases media and unmounts before `delete_project`. A failed save prevents deletion, and a failed delete leaves editable state available for retry. Successful deletion clears the current history and save snapshot before opening another project or showing the empty workspace. Request sequencing rejects stale catalog results while allowing a freshly restored project to reappear on Refresh. These tests mock the Recycle Bin command and do not delete real projects or establish Windows Shell restore behavior.

Audio preview uses one MediaElementAudioSource per recorded audio track, unity HTML media volume, separate GainNodes, and a shared stereo limiter. The standalone readable `public/audio-limiter.js` follows FFmpeg's 48kHz, limit 0.95, attack 5ms, release 50ms, asc=0, level=0 algorithm. Its 239-frame lookahead is included in auxiliary playback alignment, and seeks reset its state. Contexts and nodes are released on unmount. Initialization/processor failures remain visible and do not fall back to direct or duplicate audio. The LGPL attribution remains in the separate source file; build output was verified byte-identical to that source.

Recorded microphone, computer audio, and imported music waveforms use bounded backend min/max bins in original source time. Timeline projection follows kept spans and music in-points. Raw RMS/peak statistics cover the saved kept intervals and become visibly stale after cuts change. Normalize saves current edits, analyzes again, applies a separate source gain as one undoable change, and leaves the volume slider intact. Silent or failed analysis never substitutes a guessed gain. Background reads are cancelled and awaited before closing, project replacement, recording, import, transcription, export, or deletion. Per-job progress and results reject stale identifiers.

The explicit microphone test uses a selected native device for up to 30 seconds, polling peak/RMS at 10Hz. It never saves or plays test audio. Device changes, Cancel, Escape, Start recording, application close, and unmount stop it. Pending startup receives another stop after acknowledgment; cleanup failure blocks recording and offers Retry stop test. Headless tests mock these IPC responses and do not open physical microphones.

The separate `public/audio-ducker.js` mixes microphone, computer audio, and music as three stereo buses before the limiter. Recorded normalization gain multiplies its volume before mixing. Microphone power drives a 10ms attack/150ms release envelope, with a -40 to -30dBFS activity range; music gain uses 10ms attack/250ms release and the requested 0-24dB reduction. Computer audio is unaffected by ducking. A per-sample activity gate freezes detector state at cut deadlines and during decoded seeks. Automatic cut jumps preserve that state; explicit playback/seek resets it. Shared renderer checkpoints match within 1e-7 for float PCM and 1e-12 for internal state. The real browser worklet also matches the reference and preserves retained output when 25,600 gated loud samples are inserted. This establishes synthetic DSP parity, not physical playback synchronization.

Video edits retain chronological source intervals while the timeline and transport display contiguous output time. Split (`S`), selected-clip ripple deletion (`Delete`), and the output-range cut dialog each create one undo step. Inputs and modal controls retain their normal keyboard behavior. Source trim and clip bounds prevent empty output; no cut rewrites original media. Music, zooms, captions, and masks keep source coordinates and times. Their timeline fragments expose trim handles only at the actual original endpoints. Plain captions spanning removed declared footage stay hidden until reviewed or regenerated. Timed captions retain only words whose entire interval survives the cut; raw text stays available for Undo. Imported SRT can declare several source ranges without duplicating the sentence across those ranges.

At a cut, preview pauses every media element, closes input/output audio gates, waits for decoded seeks, and checks the current playback generation before drawing or resuming. Cut deadlines may shorten as clocks advance but cannot extend or reopen because an HTML media clock lags. The browser regression uses non-frame-aligned and non-sample-aligned cut boundaries, removed red video frames, removed 997Hz audio, and 140ms delayed seek notifications. Its PCM tap is after the real output gate. A second pass plays a retained tone and checks its amplitude and RMS, so an entirely muted preview cannot pass. Evidence is stored in `artifacts/ui/cut-privacy-evidence.json`; the synthetic fixture and screenshot are test artifacts only. These checks do not establish physical speaker latency or native WebView2 cut behavior.

Imported music enters that same limiter through a separate gain node per clip. Source offsets and linear fades use recording time. Timeline clip moves and trim handles snap to recording frames; focused clip controls also support Left/Right and Shift+Left/Right. Source trim and zoom segments have direct handles, with zooms stopping at neighboring segments. Numeric controls remain available for exact timing. Subtitle clips stop at neighboring cues; redactions use half-open intervals and enforce the 16-active-region limit. Undo/redo stores only edit settings, coalesces gestures, and retains at most 100 entries within a 16 MiB past/future budget.

Subtitles use the backend's libass PNG raster for both Unicode shaping and layout. The UI issues one raster request at a time, prioritizes the active cue before prefetching, retries superseded requests, and ignores obsolete raster results. Decoded rasters are capped at eight images and 64 MiB, prioritizing the active word and plain-text fallback. Prefetch considers at most eight distinct appearances and does not repeatedly reload evicted speculative images. Cache identity includes ordered word text and the active word index, but excludes timing; safe projected text determines whether a cached image may be shown after a cut. While an active-word image loads, the plain cue remains visible. Timing gaps use plain text and source-range gaps display no cue. The browser mock tests orchestration and display, while actual raster/export parity belongs to the renderer integration checks. Blur operates on edge-padded source-coordinate patches before crop/zoom. Canvas and FFmpeg Gaussian kernels are not pixel-identical; solid masks remain opaque black in both paths.

Local transcription is the default provider. Opening the dialog checks installed status but does not download or recognize audio. Explicit setup displays download progress, error/retry, and cancellation; Escape, provider changes, and application close await pending startup acknowledgment and terminal cancellation before leaving. Installation completion never starts recognition. Local generation sends no API key. Browser tests mock the pinned runtime/model setup and ASR jobs; real local installation, recognition accuracy, and speed are covered separately by backend evidence and manual hardware validation.

Subtitle controls support SRT import as one undoable replacement after flushing saved edits, complete-word splitting, text-caret or clearly labeled proportional splitting for plain cues, and merging the visible projected text. Text edits clear word metadata. Moving cues shifts word times and source ranges together; trimming retains whole words. SRT has no word timings and remains plain when highlighting is enabled. The numeric controls and keyboard timeline movement remain available. Import errors preserve the current cues.

Cloud transcription requires explicit submission of the upload form. The API key stays in session memory and clears after starting, failure, or dialog close. Progress is accepted only for the current project and job UUID. Generated cues replace existing cues as one undoable edit. These automated tests mock cloud responses and do not incur provider fees or validate a live Deepgram account.

Webcam preview uses `cameraTime = screenTime + cameraOffsetSeconds`, with a legacy default of zero, and hides the overlay after the actual webcam EOF. Auxiliary media errors remain visible without stopping screen preview. Webcam-disabled and zero-volume tracks are not started for playback. Tauri 2.12.5's bundled asset-protocol source sets `Access-Control-Allow-Origin` to the window origin; audio elements request anonymous CORS. This source inspection does not replace a native runtime test.

Joined camera media can also carry half-open `cameraIntervals` in source time. The preview decodes padded camera media continuously to keep its clock synchronized, but draws only when both screen and camera clocks are inside an available interval. Legacy null/absent intervals retain the prior EOF behavior. The browser regression records actual canvas draw calls through a short camera gap and verifies the kept camera frames return without drawing unavailable intervals.

The camera-preview browser tests use generated JPEG frames and mocked IPC, never physical devices. No native computer-use testing was performed for this UI revision. These tests do not establish physical webcam/microphone coverage, clean-machine installer behavior, signed-release status, or final WebView2 playback verification. Native UI testing remains manual, as requested by the user.

Recording setup keeps its heading and actions outside the scrolling body. Headless checks cover 1280x720, 900x640 and 900x480 in both themes, keyboard focus and button hit-testing, including long diagnostic errors. Recording startup failures remain inside the dialog with the original backend detail and a retry action; selected options survive the failure. Webcam selection states that the camera is included while its optional preview stays off until explicitly enabled. Device enumeration failures disable stale choices, and request sequencing rejects replies from a closed dialog. A failed camera stop retains its session token for retry without opening another camera session; native process cleanup remains the backend's responsibility. Additional regressions cover delayed startup, Cancel/Escape, native close during countdown, and filtering empty or duplicate recovery notices. These tests establish UI behavior, not the cause or resolution of a native capture failure.

The Apps source picker uses the native process/window catalog and submits the selected canonical `app:<pid>:<hwnd>` source. One app window is recorded; computer audio still includes all apps. Multiple-window apps require an explicit window choice. Refresh preserves exact valid identities, but a disappeared app or window clears the capture source until the user selects again. Search filters actual executable names and window titles without silently changing selection; Enter in search cannot submit the recording form. Unit and headless tests cover tab changes, missing/legacy catalogs, failed and stale enumeration, keyboard selection, accidental form submission, and 900x640 dark/light screenshots in `artifacts/apps-0.4.4`. Their catalog is a test fixture; native eligibility and process ownership validation belong to backend checks and manual testing.

Webcam shutdown regressions keep the mocked native Stop promise pending across 25 seconds of simulated time. Main and floating controls remain in Finalizing, reject a second Stop, prevent new recording and block close until the result arrives. Tests distinguish a ready success, an interrupted recovered project, and a genuine failed Stop with a visible diagnostic. A generated 35.5-second camera track with positive offset 0.790257 disappears at source time 34.709743; a longer elapsed-time fixture remains visible at its corresponding camera time. Neither preview route stretches legacy media or fabricates missing footage. These are decoded-media and IPC-state tests, not physical camera clock or driver shutdown validation.

Recording fault injection also covers terminal events arriving before the Start acknowledgment, a delayed health rejection after Pause, and an idle status arriving without a completion event. Results are matched to the recording project ID; an unrelated older library item cannot replace the failed session or erase its diagnostic. Floating Stop remains disabled until an active project identity is acknowledged. These cases use delayed mocked IPC and do not change or verify the backend watchdog's decision to stop a native capture.

Startup requests publish their successful results independently. A failed status request cannot discard valid app information, and failed initialization remains explicitly retryable after opening a saved project. Tests inject both status and app-information failures and verify recovery without reloading the app.


Motion tracking is explicit for a selected mask range of at most 300 seconds. The UI flushes edits and cancels waveform analysis before starting. Progress and cancellation match the project, region and job UUID; cancellation and native close wait for startup acknowledgment and terminal completion. Failed, cancelled or oversized results preserve the previous mask. Applying a result, a correction, review, clearing or deleting a keyframe is undoable. Limits are 3,002 keyframes per mask and 20,000 per project.

Tracked geometry follows the shared Rust fixture in `testdata/mask-tracking-reference.json`. Automatic endpoints use a bounding union; the rectangle holds until a manual endpoint. A lost endpoint makes the preceding interval and subsequent lost portion full-screen solid black, even for blur, until a manual correction. Tracked blur uses a cached maximum source-pixel patch size and clips its blurred output to the actual evaluated region. Static blur keeps its prior patch-edge behavior. Canvas and FFmpeg Gaussian kernels still differ; the shared geometry is deterministic, not a claim of identical blur pixels.

Dragging or editing a tracked mask adds a manual keyframe at the actual paused source time. A delayed-RAF regression verifies that the keyframe does not use the older displayed playhead emission. Trimming synthesizes conservative boundary keys with confidence inherited from the contributing keys, extending beyond known coverage inserts loss protection, and moving shifts the keyframes with the region. Effect, timing and geometry changes invalidate review; Undo restores the original review state. Export requires explicit review of active tracked masks and the native backend repeats this check. Review is an inspection step, not a guarantee that an automatic tracker identified every sensitive item.

`Draw correction on original` is a deliberate, paused inspection mode. It temporarily shows the unmasked screen frame to place a correction; no original-frame mode flag is saved or sent to export. Audio and playback stop. Escape, pointer abort, seek, tool/project changes and export attempts restore the safe composition. Headless tests verify real decoded pixels through loss and correction, job cancellation races, keyboard corrections, review/Undo, both themes and a 900x640 viewport. Tracker estimation accuracy and native hardware behavior are tested separately; these UI tests use mocked tracking results and generated video, never physical capture or computer-use automation.

Canvas Screen sizing is saved output geometry, separate from the preview's Fit/100%/200% display scale. Fit preserves the legacy frame and viewport. Fill covers the actual screen pane while staying inside the integer manual crop, centers independently of idle cursor movement, and blends active zoom focus with its scale envelope. Camera-only keeps screen hidden. The preview matches 17 independent geometry cases in `testdata/reframe-reference.json`. Browser checks verify decoded portrait/square pixels, split-camera gaps and EOF, source-mask coordinates, synchronous clearing during pending seeks, one-step Undo, save/reopen, and legacy preset defaults. Stage 1 evidence is in `artifacts/vertical-0.5.0`; it does not establish native hardware behavior.

## Video background, Stage 3 of 0.5.0

Blurred video uses the current integer, center-cover subrectangle entirely within the final foreground viewport, after source masks and before camera/captions. Fullscreen camera and original-frame inspection use solid fallback. Three scratch surfaces and up to four cached native tile shapes stay below 20 MiB, with tile edges at most 512 pixels; output scratch has a maximum 960-pixel edge. No source-time image cache is used. The native tile is necessary because a Chromium regression demonstrated adjacent-pixel sampling when directly enlarging a one-pixel source subrectangle. Tiles are copied 1:1, resized as whole canvases, and never retain outside-source pixels. Exact sentinel tests cover one-pixel and partial-tile boundaries, opacity and clearing. The same native isolation also fixes a measured pre-existing foreground crop leak; a smooth gradient comparison checks fractional tile seams and bounded shape reuse.

Eight independent background geometry fixtures supplement the 34 framing fixtures. Browser workflows exercise paused mask changes, lost tracking, crop/reframe/cut privacy, held seeks, original inspection, camera-only gaps, background controls, Undo, presets excluding keys and saved reopen. Canvas and FFmpeg blur kernels differ; matching geometry and privacy do not imply pixel-identical blur. Logs and dark/light 900x640 screenshots are in `artifacts/vertical-0.5.0/stage3-*`. Native performance and device behavior remain manual validation.
